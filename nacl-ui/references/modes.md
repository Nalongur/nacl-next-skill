# 认证模式 A/B/D

模式是工程级配置，写入 `nacl.project.json`、页面 `mode`、Cargo 默认 feature 和 SDK 能力。生成后不要靠隐藏按钮改变模式；需要换模式时生成新工程。

## A：仅正版

- 身份组件只有 `MicrosoftIdentity`；不提供本地档案组件/命令。
- 开发者/发行者通过运行环境变量 `NACL_NEXT_MICROSOFT_CLIENT_ID` 配置其有权使用的 Client ID；不预置、不复用旧 ID。
- 缺少 Client ID 时，在需要配置的正版身份节点显示配置提示，并指导注册/权限核查；不自动回退本地、不切换项目模式。
- 真实登录、权益和有效身份启动需要真实环境与授权；未执行时明确标为未验证。

## B：仅本地

- 身份组件只有 `LocalProfiles`；组件/动作/数据源都不包含 Microsoft。
- 编译不启用 `microsoft` feature，不产生 Microsoft 请求、OAuth、权益或在线账号 UI。
- 不需要 Client ID；不要在 B 工程中反复要求申请应用或配置 ID。
- 本地档案创建/命名/选择/切换及适用实例启动是默认路径；缺失文件只报告原因，不自动获取。

## D：共存

- 同时提供 `MicrosoftIdentity`、`LocalProfiles` 和 `IdentityPicker`。
- 每次启动必须在身份选择器中明确选择一种身份；启动面板显示本次使用的身份。
- 缺 Client ID 不阻塞用户主动选择的本地分支；本地启动不得借用正版凭据，也不得隐式发起认证。
- 正版失败/退出不会自动改选本地身份；两类状态与凭据隔离。
- 在 D 中选择本次启动身份不等于更改项目模式，不需要重新生成或编译。

## C：未明确

需求未明确且会影响设计或交付时，简短询问仅正版、仅离线还是共存；能独立推进的 UI/基础工作继续。不要因为缺 ID 自动选 B，也不要默认选 A/D。

## 页面能力对照

| 能力 | A | B | D |
| --- | --- | --- | --- |
| `MicrosoftIdentity` | 必需 | 不提供 | 必需 |
| `LocalProfiles` | 不提供 | 必需 | 必需 |
| `IdentityPicker` | 不提供 | 不提供 | 必需 |
| Microsoft 数据源/动作 | 可用 | 不可用 | 可用 |
| 本地档案数据源/动作 | 不可用 | 可用 | 可用 |

生成器会校验：身份组件必需项、组件/绑定/动作的模式可用性、页面 mode 与项目 mode 一致、Cargo 默认 feature 与项目模式一致。校验失败时不要通过删组件或改 Schema 绕过。

## 证据边界

- A：配置/能力边界可以离线验证；真实 Microsoft 登录、权益和有效身份启动另需授权环境。
- B：本地档案与适用实例启动可验证；本地成功不证明正版能力。
- D：显式身份选择、状态隔离和本地分支可验证；正版分支与 D 整体完成仍待真实环境。D 的本地成功不等于 D 整体通过。
- Mock 和自有 Java 探针不是真实账号、游戏或后端证据。
